# 使用说明（公开模板）

## 一、它是什么

一套装在你自己电脑上的 AI 工作台：4 个场景、4 个 AI 助手、记忆写在本地文件里。
需要你自己的 DSH（DSH 引擎）引擎——本包**不带引擎**。

## 二、第一次用

```powershell
cd 外壳
npm install
cd ..
双击 启动.vbs        # 端口 3083，不动你原有的 3080
```

然后给每个场景建会话：

```powershell
node 外壳\scripts\建会话.mjs --title "命令"
node 外壳\scripts\建会话.mjs --title "B站"
node 外壳\scripts\建会话.mjs --title "自我复盘"
node 外壳\scripts\建会话.mjs --title "本地电脑"
# 把每个命令最后一行打印的 sessionId 写回 外壳\scenarios\<场景>.json 的 sessionId / sessionTitle
node 外壳\scripts\sessions.mjs --check
```

### 3.1 面板编辑器（界面里加网页，不用改 json）

点场景标签栏**最右边的「＋」** → 弹出「面板管理 · 场景名」：

- 每个面板一行：`id`（分区键）/ 标题 / 网址 / col / row / 宽 / 高
- 「＋ 加一个网页面板」追加一行，「删除」去掉一行
- 「保存并刷新」写盘前自动备份成 `外壳\scenarios\<场景>.json.bak-edit-<时间>`，然后热刷新场景

两条要记住：

- **面板 `id` = 登录分区键**（`persist:embed-<id>`）。改 id 等于换一个浏览器分区，原来那个网页的登录态会掉。
- 编辑器只管这 7 个字段，**其余字段原样保留**（`sessionId`/`sessionTitle`/`pinTarget`/`sub`/`allowPopups`/`userAgent` 等），所以改网页不会弄丢会话绑定。

### 3.2 皮肤（和 dsh 皮肤插件同一套约定）

外观菜单（顶栏 🎨）= 明暗三档 + 5 套配色 + **皮肤组**（读 `外壳\skins\` 下的目录）。

做一个自己的皮肤：在 `外壳\skins\<id>\` 里放

```
skin.json    必填：id / name / accent / bodyAttr / order
             选填：nameEn / author / tagline / background（背景图相对路径）
                   backgroundOpacity / desktopIcon（.ico）/ vars（CSS 变量覆盖）
skin.css     可选：写 body[data-dsh-<id>]{...} 的覆盖样式
```

- `bodyAttr` 会挂到 `<body>`（例如 `data-dsh-deepsea`），CSS 就靠它命中 —— 与 dsh 前端皮肤插件一致
- `vars` 直接覆盖 `--bg / --bg-panel / --border / --text / --accent` 等变量
- `background` 走一层 `#skin-bg-layer`（`z-index:-1`），不需要改任何现成元素
- `desktopIcon` 只换窗口/任务栏图标（`BrowserWindow.setIcon`），不动注册表和快捷方式
- 自带两套示例：`deepsea`（深海鲸）、`sunset`（落日橘）。`_` 开头的目录会被跳过（可当草稿区）

我只想换一张背景图（不写皮肤）：外观菜单 → **背景图** →

| 菜单项 | 做什么 |
|---|---|
| 🖼 上传一张图片… / 换一张图片… | 选 png / jpg / jpeg / webp / gif / bmp / avif，复制成 `外壳\skins\_user\bg<后缀>`，只留一张 |
| ◐ 浓淡：N% | 点一下循环 25% → 45% → 65% → 85% |
| ✕ 去掉背景图 | 删掉 `bg.*` 与 `bg.json`，背景层归零 |

实现：`外壳\skins\_user\bg.json`（`{file, name, opacity}`）+ 一个 `#skin-bg-layer`（`z-index:-1`），标题栏/场景栏/面板会自动半透明让图透出来（`html[data-skin-userbg="1"]`）。用户图**优先于**皮肤自带的 `background`。

#### 卡片颜色自动跟着背景图走

**一张图当整个工作台的底，卡片的底色/描边/强调色/文字色温全部从这张图的像素里算出来。** 换任何一张图都自动配套，不用手写配色。

- 采样在**主进程**做：`nativeImage.createFromPath().resize(32×32).toBitmap()`，不经过 canvas，所以没有 `file://` 图把 canvas 污染成"读不出像素"的问题
- 强调色取**出现最多的那个色桶**（不是最饱和的桶 —— 一张暖灰风景里只要有一小块蓝天，挑最饱和就会跳成冷蓝，整台打架），再保色相推到"能当高亮用"的饱和度/亮度
- 卡片是**深色玻璃**不是"图的平均色"：图越亮压深的那层越实（`lum > 55 → alpha 0.74`，`35~55 → 0.66`，`< 35 → 0.52`），否则 0.59 的灰盖在 186 亮度的图上会变成中灰 + 白字，字全糊
- 文字色温也跟着走：暖图给 `#f2ede6`，冷图给 `#e8ecf3`
- 结果会**覆盖** `skin.json` 里写死的 `--bg / --bg-panel / --bg-panel-hover / --border / --accent / --accent-soft / --ring / --tech-line / --text / --text-dim`；取色失败就退回 `skin.json` 里的兜底色

调试时在窗口里执行：

```js
window.__skinPalette     // {ok, avg:[r,g,b], accent, dark, panel, lum, size}
```

`lum` 是整张图的平均亮度（0~100），卡片玻璃的实心程度就是按它算的。

### 3.2.1 卡片主题（每张卡片单独一张背景图）

皮肤是**整个工作台**一层，卡片主题是**单张卡片**一层 —— 两套互不干扰，可以同时开。

最省事的用法：**右键卡片标题**，弹出来的菜单就是全部入口。

| 菜单项 | 做什么 |
|---|---|
| 🖼 换一张背景图… | 选图，存进 `外壳\skins\_cards\<卡片id>\bg.<后缀>` |
| ◐ 浓淡：N% | 点一下循环 15% → 25% → 35% → 50% → 70% → 90% |
| ⤢ 显示：铺满裁切 / 完整放进 / 平铺 | 对应 `background-size: cover / contain / repeat` |
| ✕ 去掉这张卡片的背景 | 删掉这张卡的目录 |

落盘格式和最上面那个 `topic\` 目录一个思路 —— **一个目录、一张图、一份 json**：

```
外壳\skins\_cards\<panelId>\
  card.json    { "panelId": "cmd-neuron", "name": "灰夜",
                 "file": "bg.jpg", "opacity": 0.3,
                 "accent": "#8fa6bf", "fit": "cover", "updatedAt": "..." }
  bg.jpg       实际图片（png/jpg/webp/gif/bmp/avif 都行）
```

- `<panelId>` 就是场景 json 里每个 `panels[].id`：`cmd-neuron` / `cmd-plan` / `bv-web` / `bv-ai` / `myweb-web`
- `opacity` 夹在 0~1（默认 0.35），`fit` 只认 `cover|contain|repeat`
- `_cards` 这个下划线目录会被皮肤扫描跳过，不会当成皮肤
- 卡片主题挂在 `.panel` 里的一层真实元素 `.card-bg-layer`（`z-index:0`），标题栏和正文抬到 `z-index:1`，所以图永远不会盖住字

**批量整理图片**：把图先按卡片 id 命名（`cmd-neuron.jpg`、`cmd-plan.png`…）丢进一个目录，然后

```bat
node 工具\主题打包.mjs --list                       :: 看现在谁有主题、谁还没有
node 工具\主题打包.mjs --panels                     :: 列出所有卡片 id 和所属场景
node 工具\主题打包.mjs --from "D:\AAAlingmindu_workbench\topic"   :: 按文件名自动配对
node 工具\主题打包.mjs --all --file 某张图.jpg       :: 一张图铺满所有卡片
node 工具\主题打包.mjs --panel cmd-plan --file 图.jpg --opacity 0.22
node 工具\主题打包.mjs --panel cmd-plan --clear
```

`--from` 支持前后缀模糊（`cmd-neuron-夜色.jpg` 也能配对到 `cmd-neuron`），加 `--dry` 只打印不动手，加 `--force` 覆盖已有的。

注意：`bv-web`、`bv-ai`、`myweb-web` 这三张里装的是 `<webview>`（网页本身），背景层会被网页整个盖住，**配了也看不见** —— 能看见效果的是 `cmd-neuron`（记忆神经元）和 `cmd-plan`（每日计划）这类自绘卡片。

### 3.2.2 背景图也铺进引擎页面（DeepSeek Harness 里面）

「一张图当整台工作台的底」到 `.panel` 为止是不够的 —— `bv-ai` 那张卡片里装的是 **dsh 引擎自己的网页**（`http://127.0.0.1:3093`），它是另一个页面，皮肤 CSS 管不到它。所以换皮肤 / 换背景图的时候，工作台会**把同一张图也塞进那个页面里**。

不需要任何操作：选图、换皮肤、上传自定义图，都会自动同步。分三种情况：

| 页面 | 处理方式 |
|---|---|
| 外壳自己的面板（每日计划、标题栏、场景栏） | 皮肤 CSS 直接管，`#skin-bg-layer` + 半透明磨砂 |
| 记忆神经元那张卡片 | **canvas 自绘**（见 3.2.3 —— CSS 背景层在它里面画不出来） |
| 内嵌的 dsh 页面（`bv-ai`） | 注入：`#wb-skin-bg` 铺底 + 把大块不透明底色改成半透明 |
| `bv-web` / `myweb-web` 里的外部网站 | **不动** —— 人家有自己的完整页面，不该被我们染色 |

dsh 页面里的注入做了三件事：

1. 插一层 `position:fixed` 的 `#wb-skin-bg`（`z-index:0`）铺满视口，图用 **base64** 塞进去（`skins:bg-dataurl`，缩到 1920 宽、JPEG q82，约 550KB）—— 因为 Chrome 不允许 `http://127.0.0.1:3093` 的页面引用 `file://` 的图
2. `html` / `body` / `#root` 背景改透明，`#root` 抬到 `z-index:1`
3. 扫一遍页面里「面积 ≥ 视口 6% 且计算值是不透明 `rgb()`」的容器，把底色改成 `rgba(...,α)`

第 3 步有两个坑，都在实现里绕开了：

- **不能按类名改**：dsh 的类名是 CSS Modules 带 hash 的（`pI_x6G_frame`、`hz8-rW_card` 这种），引擎一升级就失效。所以按「面积 + 原本是否不透明」现场扫。
- **半透明会层叠复利**：`frame(.74)` > `tabHost(.74)` > `root(.74)` 三层合成就是 98%，图完全看不见。所以先数出互相嵌套的层数，**最外层给 α、里面每层只给 0.16**，三层合成大约 0.73。α 跟着图的亮度走（`lum > 55 → 0.62`、`35~55 → 0.68`、`< 35 → 0.75`），和卡片的判断是同一套。
- 改完的底色是 `rgba(...)`，而扫描只认 `rgb(...)`，所以**重复执行天然幂等**，不用打标记。
- dsh 是 React，块是陆续渲染出来的（面板级容器比外框晚好几拍），所以挂了个只看 `childList` 的 `MutationObserver` 持续补色（60 秒后自动断开，不监听属性，免得自己改样式把自己叫醒空转）。

页面加载完（`did-finish-load`）会补注入三次（0 / 1.5s / 4s）—— SPA 渲染是渐进的，晚一拍才能把后来才出现的块也染上。换图换皮肤则立刻重注。

验证（在 dsh 页面里跑）：

```js
document.getElementById('wb-skin-bg').getBoundingClientRect()   // 铺满视口
document.querySelector('.pI_x6G_frame').style.backgroundColor  // rgba(21,21,23,0.62)
```


### 3.2.3 神经元的底也是同一张图（canvas 自绘）

记忆神经元这张卡片的背景图是**画在 canvas 里的**，不是 CSS 背景。

原因是一个坑：`#skin-bg-layer`（`position:fixed` + `z-index:-1`）、`html`/`body` 的 `background`、甚至 `#grid` 自己的 `background-image`，在这个 Electron 窗口里**都画不到屏幕上**。验证方法很干脆 —— 把那一层刷成纯绿 `#00ff00`、`z-index` 改 0，截图里**一点绿都没有**；只有 `.panel-head` 的 `backdrop-filter` 还能采到图（所以滚动条缝隙和标题栏看着是亮的，面板里面是黑的）。

canvas 自己画的内容一定看得见（节点本来就画得好好的），所以直接 `drawImage`：

- `外壳\renderer\renderer.js` 的 `refreshBgLayer()` 把 `{src, opacity}` 写到 `window.__neuronBg`，然后调 `window.__neuronRedraw()`
- `外壳\renderer\renderers.js` 的 `paintBgImage(ctx)` 在 `clearRect` 之后、画节点之前，按 **cover**（等比铺满 + 居中裁切）`drawImage`，透明度 = `皮肤 backgroundOpacity × 0.72`
- 图是异步加载的，`onload` 里会再 `markDirty()` 一次，所以打开时先空一下、图到了自己补上

配套的两处调整（有图时才生效，看 `html[data-skin-bg="1"]`）：

- 神经元面板底板不再单独调淡 —— 它和别的卡片走同一套「背景即主题」材质（见 3.2.4），底板浓淡由图的亮度算
- canvas 里的中心微光 `rgba(30,54,96,.55)` → `.14`、暗角 `rgba(2,4,9,.55)` → `.20`，图才吃得消
- 画图参数在两处：`renderers.js` 的 `ctx.filter`（`blur(14px) saturate(.82) brightness(.66)`）和 `globalAlpha`（`皮肤 backgroundOpacity × 0.72`）。**图太抢戏／节点看不清就调这两个数**，三个参考档写在代码注释里

换皮肤 / 换背景图 / 调浓淡都会立刻重画，不用重启。


### 3.2.4 背景图当主题（不是"图 + 几块黑玻璃"）

以前是：底下一张图，上面盖几块固定的深蓝黑玻璃 —— 图的颜色跟界面没有任何关系，像贴纸。
现在是：**图就是主题**，界面每一块不透明的黑色，都换成"图在那个位置的颜色压深一点"。

**颜色全是从图里算出来的**（`外壳\main.js` 的 `paletteOfImage()`）：

| 算法 | 干什么 |
|---|---|
| 缩到 48×48 + 4bit 色桶投票 | 找出主色 → `--accent` |
| 同法找色相差 >28° 的第二种色 | 次强调色 → `--accent-2` |
| **切 3×3 网格**，每格单独求平均 | 每格出两个色：`glass`（压暗 72%，当底板）、`tint`（提亮，当描边和反光） |
| 全图平均压暗 74% | `--glass` / `--glass-rgb`，顶栏、场景栏用它 |
| 平均亮度 `lum` | 决定玻璃浓淡（亮图 0.68 / 中间 0.60 / 暗图 0.48）和文字色温（暖图给暖白） |

于是**同一个窗口里两张卡片的底色是不一样的** —— 左边那张在图的左边，取的是左边那块颜色；右下那张取右下那块。实测这张日出图：正中偏暖褐 `rgba(58,47,45)`，右下偏紫 `rgba(43,39,44)`。

**变量从哪来、挂在哪**

- `外壳\renderer\renderer.js` 的 `applySkinPalette()` 把 palette 写成 22 个 CSS 变量（`--accent / --accent-2 / --glass-rgb / --glass-a / --glass-line / --panel-rgb / --panel-line / --text / --swatch-1~3` …）
- 同文件的 `applyPanelTints()` 按每个 `.panel` 的 `getBoundingClientRect()` 中心点换算成 3×3 格，把那一格的颜色写到这张卡片自己的内联变量上
- `外壳\renderer\styles.css` 末尾一整个「背景即主题」段落，每条规则都挂 `html[data-skin-bg="1"]` 前缀 —— **没有背景图时一条都不生效**，自动退回原来的暗色

**几个必须知道的坑（都踩过）**

1. `#scenebar` 那条规则必须带 `!important`。styles.css 里面更早的"省电版"写着 `#scenebar { background: rgba(13,16,24,.80) !important }`，**带 !important 的声明永远压过不带的那条**，不管你的选择器特异性多高。
2. 面板的图色要**反复补**。两个原因：取色 IPC 比首屏快（面板还在 DOM 里没布局，`getBoundingClientRect()` 是 0×0，会被跳过）；场景是重渲染的（切场景／换皮肤时 `.panel` 元素整个换掉，新元素身上没有内联变量）。所以 `watchPanelTints()` 挂了 `MutationObserver`（300ms 节流）+ 4 秒低频兜底（窗口不可见时不跑）。**别改成"试 N 次就停"的定时器**，那样切一次场景就掉了。
3. 截图验证只能用 CDP 默认的 `fromSurface`。`SHOT_NOSURFACE=1`（渲染进程本地合成）在这个窗口里时灵时不灵，会整片全黑，误判成"代码没生效"。
4. `外壳\skins\<id>\skin.css` 里**不要再写颜色**。以前 huiye 的 skin.css 用 `background: … !important` 把场景栏压成死色，新主题段就被它盖住了。现在它只管 `backdrop-filter` 和 box-shadow。

**换一张图 = 换一套主题**，不用手写任何 `skin.json` 里的颜色。


### 3.3 每日计划（固定时间的固定事 + 自己在推的项目）




命令场景下方那块「每日计划」，数据在 `引擎数据\.dsh\场景记忆\_共享记忆\每日计划.json`：

```json
{ "version": 1, "items": [
  { "id":"p1", "title":"晨间三件事", "time":"08:30", "days":[], "kind":"routine",
    "due":"", "note":"", "since":"2026-11-25", "until":"", "logs":{"2026-11-25":{"done":true,"at":"..."}} }
] }
```

- `days` 空 = 每天；`1,3,5` = 周一三五（1=周一 … 7=周日）
- `kind`：`routine` 固定计划（按 `days` 出现）/ `project` 自己的项目（只看 `due`，没做完就一直出现）/ `once` 一次性
- 勾选 = 往 `logs[当天]` 写 `done`，**只写这一个文件**，写完自动备份 `.bak-plan-<时间>`

面板上能做的：勾一下 / ✕ 删一条 / ＋ 加一条（当场填标题、时间、星期、类型、截止、备注）/ ↻ 重读。

命令行：

```bat
node 工具\每日计划.mjs                          :: 今天该干什么
node 工具\每日计划.mjs --week                   :: 未来 7 天
node 工具\每日计划.mjs --add "写周报" --time 18:00 --days 5
node 工具\每日计划.mjs --add "把某件事做完" --kind project --due 2026-12-05
node 工具\每日计划.mjs --done p1                :: 今天标记完成（--undone 撤销）
node 工具\每日计划.mjs --remove p3              :: 删一条
node 工具\每日计划.mjs --ws list                :: 看 dsh 有哪些工作区（拿 id）
```

#### 把计划交给某个工作区做

每条计划可以有 `workspace` 字段（存 dsh 的 workspaceId，不是路径）：

```bat
node 工具\每日计划.mjs --ws list                       :: 先看 id
node 工具\每日计划.mjs --add "跑点云配准" --kind project --ws 4dad1224-9602-452b-95e2-7097a4b86539
```

面板上加一条时，最后那个下拉框就是「工作区：不指定 / 具体某个」，行上会显示工作区徽章；点行尾的 **▶** 会在那个工作区里开一个会话做这件事（`session/create` + `session/rename` 成「计划 · 标题」）。
注意 dsh 建会话本身要 **10 秒以上**（实测 14.4 秒，是引擎在 seed），点完按钮会变暗闪动并显示「正在开会话…」，别连点。

每次改动都会同时重写两处镜像，方便 dsh 里的 AI 直接读到：

- `工作区\今日计划.md`（给人看，也在这个目录的 dsh 工作区里）
- `引擎数据\.dsh\场景记忆\_共享记忆\今日计划.md`（给记忆那套工具看）

镜像里有「## 今天」「## 全部计划」「## 工作区对照」三段，工作区对照会把每个工作区的 id、路径、会话数列出来，AI 一眼就能挑 id 绑计划。
dsh 侧还有个技能 `skills\今日计划\SKILL.md`，在那儿说「今天要做什么」「加一条计划」「把这件事交给某某工作区」它就会去读/改。
（技能原文这份仓库里也留了一份：`说明\skills\今日计划\SKILL.md`。换机器时把它复制到 `引擎数据\.dsh\skills\今日计划\SKILL.md` 即可。）

神经元面板里也会出现：一个「今日计划 N 项·完成 M」的聚合点，下面挂每条今日项（`⏰ 08:30 …` 未完成 / `✓` 已完成 / `📋` 无时间）。

### 3.4 运营后台：闲鱼 / 小红书 / 抖音 / X 一屏看

场景「🧩 运营后台」（`外壳\scenarios\platforms.json`）里四块网页面板并排，各占一角：

| 面板 | 地址 | 你要看的东西 |
| --- | --- | --- |
| 闲鱼 · 卖家中心 | `https://www.goofish.com/personal` | 我卖出的 / 我发布的 / 消息 |
| 小红书 · 创作中心 | `https://creator.xiaohongshu.com/` | 笔记数据 / 发布 / 评论 |
| 抖音 · 创作者服务 | `https://creator.douyin.com/creator-micro/home` | 数据概览 / 作品管理 / 评论 |
| X · 后台数据 | `https://x.com/home` | 主页 / 通知 / 分析 |

四块都是 `embed` 面板，用的是自带浏览器内核（`userAgent: 'chrome'`）。**每个面板一个独立分区**（`persist:embed-pf-xianyu` 这样），所以：

- 登录一次就记住，关掉工作台再开还是登着的；
- 四个账号互相不串（分区隔离，不会退一个掉全部）；
- 登录页跳转是站点自己的行为（比如小红书会把你送到 `/login`），登录完就留在后台页。

不想看的时候点面板右上角的 **⛔ 取消内置**：网页会被摘掉、进程释放，登录态还在分区里；点 **🔗 内置** 就回来。四个网页 = 四个独立 guest 进程，全开着会多占一点内存和 CPU（实测四块 `<webview>` 会把 renderer 的 CPU 推高），所以不常用的那两块可以关掉。

想加第五个平台，就照 `platforms.json` 里任一 `pf-*` 复制一段改 `id / title / url / col / row`；或者直接在工作台里用面板编辑器加（见 3.1）。

#### 让 AI 读到后台的数据：📋 抓这一页

面板右上还有个 **📋 抓这一页**。点它会把当前这一页的**标题 / 正文 / 表格 / 链接**抽出来（只读 DOM，不改页面），落两份：

- `外壳\data\captures\<面板id>-<时间>.json` —— 原始结构化数据（每次一份，留着对比历史）
- `引擎数据\.dsh\场景记忆\_共享记忆\平台数据\<面板标题>.md` —— 给人看也给 AI 读的 Markdown，**每家后台一份、每次抓取整份覆盖**（只保留最新一次，不会越滚越大）

抓完面板中间会闪一行「已抓 N 字 · 表 M 个 · 链接 K 条」，告诉你落在哪。

这份 md 同时会出现在记忆神经元里（「共享」那一圈多一个点，标签就是平台名），点开能直接看正文 —— 也就是说：**在网页里登录 → 点抓取 → 神经元或 dsh 里的 AI 就能读到后台长什么样**。

两点要说清楚：

1. **没登录抓到的只是页面的壳**（导航、页脚、"请登录"），不是你的数据。先在面板里登录，再抓。
2. 抓的是**当前这一页**。要看「我卖出的」就切到那个标签页再抓；要逐页翻数据的话，现在是手动点，后面可以按需加"翻页抓取"。

> RAG 检索已经不在这块里了 —— 2026-11-26 拆成了独立的场景标签「RAG 检索」（见 3.5），一整屏都给它。

### 3.5 RAG 检索（独立场景，接自己的库不用改代码）

**场景标签上的「RAG 检索」**（`外壳\scenarios\rag.json`，2026-11-26 从「运营后台」里拆出来单独一个工作台）就是给以后的 RAG 库留的位置 —— 一整屏都是它，方便问答和看命中片段。它本身不认识任何向量库，只认两种"说话方式"：

**方式一：HTTP 服务**（推荐）

- `POST {baseUrl}{queryPath}`（默认 `/query`），请求体：`{"query": "…", "topK": 8, "collection": "…"}`
- 返回体里只要有 `hits` 数组就行，每条至少给 `text`，`score` 和 `source` 可选：

```json
{ "hits": [
  { "text": "……片段正文……", "score": 0.923, "source": "笔记-甲.md" }
] }
```

兼容别的写法：返回体的顶层键可以是 `hits / results / matches / documents / chunks / data / items / context`（也认 `data.hits`）；正文可以是 `text / content / pageContent / chunk / body`；来源可以是 `source / file / path / url / title / doc_id` 或 `metadata.*` / `metadata.source`。所以 LangChain、LlamaIndex、Dify、FastGPT、RAGFlow 这类默认返回体基本直接能接。

**方式二：本地命令**

`cmd` 填一行命令（例：`node D:\myrag\query.mjs`），工作台执行它，把同一个 JSON 从 stdin 喂进去，从 stdout 取同一个 JSON 回来。命令里自己读环境变量、连本地库都行。

**怎么配**

1. 切到场景标签 **RAG 检索**，面板右上 **⚙ 设置**；
2. 填 `baseUrl`（或 `cmd`）、需要的话填 `apiKey` / `collection` / `topK`；
3. 保存 —— 写进 `外壳\data\rag.json`；
4. 点 **⟳ 体检**：绿点表示通了（显示耗时）；红点会写明是连不上还是 HTTP 几。

之后在下方输入框问一句、回车，命中的片段按分数从高到低列出来，点任意一条复制正文。

**这个文件长什么样**（`外壳\data\rag.json`）：

```json
{
  "baseUrl": "http://127.0.0.1:8080",
  "apiKey": "",
  "queryPath": "/query",
  "healthPath": "/health",
  "topK": 8,
  "collection": "",
  "timeoutMs": 20000,
  "cmd": "",
  "note": "……说明文字，随便改……"
}
```

`baseUrl` 和 `cmd` 留空就是"未配置"（面板会给灰点提示）。`timeoutMs` 默认 20 秒。

**给写插件的人**：主进程侧一共四个 IPC —— `rag:config`（读配置）、`rag:save`（写配置）、`rag:health`（探活）、`rag:query`（检索，返回 `{ok, hits:[{text,score,source}], ms, via, url, err}`）。渲染侧只依赖 `window.app.rag.{config,save,health,query}`，所以以后想在别的场景、别的面板里也用 RAG，直接调这四个就行，不需要碰面板代码。

换机器时不用手搓配置：`外壳\data\rag.json` 不在仓库里（data 目录不跟仓库走），模板留了一份在 `说明\rag.example.json`，复制过去改字段即可。

### 4.1 记忆神经元在看什么（和 dsh 引擎同步的那部分）

面板「记忆神经元」不是手绘图，它的数据来自两处：

- **工作台自己的**：`引擎数据\.dsh\场景记忆\`（场景私有记忆 / 索引 / 项目 / 记忆地图）
- **dsh 引擎的**：`node 工具\记忆同步.mjs` 把引擎真实数据抽成 `_共享记忆\记忆地图.json` 的 `dataSources`

同步的内容：每个**工作区**（名字 + 路径 + 会话数）、每个**会话**（标题 + 最后一句话的摘要 + 轮数 + 是否归档 + 最后活动时间）、技能 / 插件 / MCP / token 账 / 体检。

数据从哪来（dsh 自己存的）：

| 数据 | 位置 |
|---|---|
| 工作区（id / 路径 / 会话列表） | `引擎数据\.dsh\storages\workspace.json` → `tables.workspaces` |
| 会话索引（cwd / 用量 / 沙箱模式） | `引擎数据\.dsh\storages\session_projcache\sessions\session-*.json` |
| 会话正文（标题 + 摘要来源） | `引擎数据\.dsh\sessions\<cwd 编码>\<id>\session.v4.jsonl.zstd` |

命令：

```bat
node 工具\记忆同步.mjs            :: 正式写盘（首次会备份 记忆地图.json）
node 工具\记忆同步.mjs --check    :: 只看不写
node 工具\记忆同步.mjs --fresh    :: 忽略摘要缓存全量重解（慢，几秒）
```

打开神经元面板时会自动同步一次，之后**每 60 秒自动重读一遍**（面板不可见时跳过，销毁时清定时器），所以 dsh 那边新开会话/归档会话，这边最多一分钟就跟上。点 ↻ 重读会绕过 30 秒节流立刻强刷。节点上：青色大球是工作区，小球是会话，悬停就能看到那句话的摘要。

#### 把没用的会话清掉

dsh 用久了会攒一堆空会话（没标题）和「未分组」（不属于任何工作区）的会话，它们会一直挂在神经元上：

```bat
node 工具\会话整理.mjs            :: 只报告：多少条未命名、多少条未分组
node 工具\会话整理.mjs --apply    :: 真归档（可回滚：只打 archived 标记，不删正文）
node 工具\会话整理.mjs --keep 5   :: 最近 5 条一律不动（默认 3）
node 工具\会话整理.mjs --age 7    :: 只整理 7 天以前的
node 工具\会话整理.mjs --ws AAA刷B站 --apply   :: 把某个工作区名下的会话全部归档
```

判据：`未命名` = dsh 里没有标题或 `blank`；`未分组` = 不属于任何工作区；`running` 和「已归档」的一律不动。
归档用的是 dsh 自己的 `workspace/archiveSession`，所以侧边栏里立刻就变灰，随时能在 dsh 里取消归档。

**侧栏「未分组」里挂着明明已归组的旧会话怎么办** —— 用 `--ws` 那一行。原因：工作区归属以**引擎内存**为准，直接改 `storages\workspace.json` 只动了磁盘，引擎不会重读（它下一次写盘反而会把改动盖回去），所以那种会话在侧栏里一直留在「未分组」。`--ws <工作区标题>` 直接走 rpc 把它们归档，侧栏立刻就没了（正文还在，能取消归档）。

### 4.2 点开一条对话：流程拓扑 + 对话全文

神经元不只是看分布 —— **点一个会话球，详情里会多出两个按钮**：

| 按钮 | 打开什么 |
|---|---|
| 🧭 流程拓扑 | 这条会话的**纵向时间轴**：每一轮一个节点组（上框＝你说的话，下框＝它的答复），节点右边写 `+N 步`（这一轮和下一轮之间引擎跑了多少次事件，含工具调用）；顶部是 9 个统计块和一条**上下文构成条**（system / tools / skill / inject / user / assistant / tool 各占多少 token） |
| 💬 对话全文 | 把 `session.v4.jsonl.zstd` 解出来，只留**你真打的字**和**它每轮的最终答复**，按轮次排开 |

点拓扑里任意一轮的「它答」框，会自动切到全文并跳到那一轮（`.jump` 高亮）。

数据怎么来、为什么只留这么点东西，值得知道：

- 轮次大纲来自 dsh 的 `session/list` 投影字段 `turnOutline`，**不是每条会话都有**（当前 409 条里只有 17 条带）。所以点开有些会话会看到「引擎没给这条会话的轮次大纲」—— 那不是坏了，是引擎还没给这条会话算投影（多半没跑过或只有一两步）。
- 全文是工作台自己解归档：`user/message` 里 `data.source.kind` 有 `user`（真人）/`time-context`/`runtime-context`/`skill-catalog`/`tool-jobs`，**只认 `user`**；`assistant/message` 用 `replayState.response.stopReason` 判，**只认 `stop`**（`toolUse` 全是工具调用的中间步骤）；`content[]` 里 `type` 有 `text` 和 `reasoning`，**只认 `text`**，否则会把模型的思考过程当正文贴出来。
- 归档路径是 `引擎数据\.dsh\sessions\<cwd 编码桶>\session-<uuid>\session.v4.jsonl.zstd`，桶名按 cwd 编码来，**每条会话的桶不一样**，所以是扫目录找，不是拼路径。
- 那份 zstd 是**多帧追加**的（一个文件里几千个 `28 B5 2F FD`），一次 `zstdDecompressSync` 只解第一帧 —— 工作台按 magic 逐帧解再拼起来。
- 全文默认只给最近 60 条；一份 5 MB 的归档解完要 5 秒左右，第一次点慢是正常的，之后同一条会话有缓存。

命令行也能拿到同样的东西（调试用）：

```js
await window.app.neuron.flow('session-<uuid>')        // 拓扑数据
await window.app.neuron.messages('session-<uuid>', 80) // 全文，第二参数是条数上限
```

### 4.3 让某个插件单独占一个工作区（以「刷B站」为例）

「刷B站」跑到点会自己起一个个值班会话，它们原先全都堆在侧栏「未分组」里。原因是**这些会话的 cwd 是插件自己在读的那个目录**，而 dsh 侧栏按 cwd 把会话归到工作区 —— 目录没登记成工作区，就只能进「未分组」。

所以两步：**把插件的目标目录换成一个真工作区**，再补历史。

**第一步：换目录（立刻生效，不用重启引擎）**

改 `引擎数据\.dsh\profiles\web\cordis.patch.yml` 里 `dsh-bili-scroll` 那段：

```yaml
    workspace: "D:\\AAA刷B站"
```

这行是插件的 `workspace` 设置，插件把它当成值班轮的 cwd，并会顺手 `workspaceRegistry.resolveByPath()` 把目录登记成工作区。改完**热加载立刻读到**，验证：

```bat
:: 在工作台窗口里执行（或看 dsh 的插件设置页）
curl "http://127.0.0.1:3093/api/bili-duty/workspaces"
:: 返回里的 current 应该已经是 D:\AAA刷B站
```

⚠️ 插件自己还存着一份 `引擎数据\.dsh\bili-duty\config.json`（里面的 `"workspace"`）。它只在 dsh 原生设置层没有该键时才生效，但改 patch 时**顺手把这份也对齐**，免得哪天原生层丢了又回落旧目录。

**第二步：把历史会话补登记进去**

dsh 只会在「新建会话时带了工作区」那一刻写归属，事后没有任何 rpc 能把老会话搬走（`workspace/addSession`、`workspace/moveSession` 全是 404；`workspace/pinSession` 只是全局置顶，不是归属）。而引擎运行期间只用内存态，**改盘会被它整份覆盖回去**，所以只能在引擎停止时改：

```bat
:: 想现在生效：双击根目录的 刷B站归组.cmd（会停引擎→改盘→起引擎，正在跑的对话会中断）
:: 或者什么都不做，下次引擎冷启动时 外壳\main.js 会自动跑一遍
node 工具\工作区归组.mjs --from "D:\AAAdafeiyu" --to-path "D:\AAA刷B站" --unarchive
```

| 参数 | 作用 |
|---|---|
| （不带参数） | 干跑：按 cwd 把「不属于任何工作区」的会话归到同路径的工作区 |
| `--apply` | 真写 `workspace.json`（先备份 `.bak-regroup-*`） |
| `--from <cwd>` | 只处理这个 cwd 的会话 |
| `--to <id>` / `--to-path <目录>` | 归到哪个工作区（id 或路径） |
| `--unarchive` | 顺手取消归档，否则归了组也看不见（侧栏默认不列已归档） |
| `--once` | 写标记 `storages\.regroup-once.done` 后不再跑 |

`--once` 是给自动执行用的：不然以后你在同一个目录下新开的普通会话，也会被下一次启动拖进刷B站。


## 五、常见问题

| 现象 | 处理 |
|---|---|
| 双击 启动.vbs 提示没装依赖 | 先 `cd 外壳 && npm install` |
| 启动后停在引擎页 | 点顶栏的场景标签；或等 10 秒它会自动进「命令」 |
| 面板空白 | 顶栏 ⟳ 刷新；再不行看 `外壳\server.log` |
| 端口被占 | 改 `启动.vbs` 里 `DSH_PORT`（默认 3083） |
| 想换引擎位置 | 改 `引擎\` junction 指向你的 DSH 引擎目录 |
| 设置里只有启动动画 | 正常：公开版只带这一个插件 |
| 顶栏那排网页版 AI 图标没了 | 正常：`renderers.js` 的 `WEB_AI_DISABLED = true`、`main.js` 的同名开关 + 不监听 31239。想恢复把两处都改 false |
| 标签栏只有「命令 / B站」 | 正常：`pc-cleanup`（本地电脑）与 `self-review`（自我复盘）的场景 json 已移出，原件在 `外壳\data\deleted-scenes\`，要回来复制回去重启即可 |
